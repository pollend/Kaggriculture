Model guide

How the DQN Job Scorer Works

The model does not control the entire farm directly. Rules create concrete jobs and handle navigation and market orders; a compact Q-network learns which field job each unit should pursue from the current state.

The core idea

A normal DQN chooses among a fixed list of actions. Kaggriculture has a variable number of possible jobs: water this plant, harvest that crop, plant a melon on one of many empty tiles, or return a particular worker's inventory to the shed. Instead of producing one output per fixed action, this model evaluates each candidate independently.

Qθ(state, job, unit) → expected discounted return

The same network is applied to every candidate. The highest allowed Q-value becomes the unit's selected job.

64maximum candidate jobs in one turn
72features for one state/job/unit row
1scalar Q-value produced per candidate
What remains rule-based: legal job construction, pathing one tile per turn, job commitment, selling crops, hiring hands, buying seeds, and endgame liquidation. The network learns field-job priority—not the full action dictionary.

Units are assigned sequentially

The farmer chooses first, followed by hands in observation order. Once a non-pass job is selected, it is marked as taken so another unit cannot select the same candidate in that turn. Unit-owned jobs such as DROP are masked from everyone else.

Travel uses commitments

If the job is remote, deterministic routing emits one movement action and remembers the target. The unit keeps walking until it arrives, the job disappears, or 20 turns pass. Exploration happens when choosing a job, not on every travel step.

Why commitment matters: without it, small Q-value changes can make a unit alternate between two destinations and never reach either. The 3rd unit feature marks the committed candidate so the network can distinguish otherwise identical board states.

The candidate job space

jobs.py converts the variable farm state into concrete candidates. PASS is always index 0; other jobs attach a target tile, game action, optional crop, optional tile state, and optional owning unit.

JobCreated whenNetwork is deciding
PASSAlwaysWhether doing nothing is preferable
WATERA plant is not watered todayWhich plant is most urgent
HARVESTA plant has reachable yield at or after first yield dayWhether and where to harvest
PLANTAn empty tile and owned seed form a valid pairWhich crop and tile deserve labor
DIGA tile contains a weedWhen clearing space is worth the travel
FERTILIZEFertilizer exists and a plant is not currently fertilizedWhich plant should receive the bonus
DROPA unit carries inventoryWhen that specific unit should return to the shed

Candidate count is capped at 64. If the raw set is larger, the enumerator pins PASS and unit-owned jobs, then prioritizes endangered watering, harvesting, ordinary watering, maintenance, and finally planting. Truncations are recorded for training diagnostics rather than hidden.

Current strategy boundary: the learned job set is crop-focused. It does not build animal structures, feed or care for animals, collect animal products, buy land, or learn market orders. See the technical review for limitations and known correctness concerns.

The 72-value input

Feature construction lives in features.py and is shared by training and inference. A layout change invalidates old weights, so the dimensions are explicit and parity-tested.

BlockSizeContents
Global state 43 Time and season progress; own and opponent money; seed counts; shed crops and fertilizer; market price and inventory signals; hands and hires; planted, empty, weed, unwatered, and harvestable counts; unlocked quadrants; carried inventory; shed headroom.
Static job 26 Job-kind one-hot; crop one-hot and crop-present flag; plant age, maturity, yield, missed water, current water, bonus window, and fertilization; crop price ratio, seed cost, ongoing flag, season feasibility; target distance from the shed.
Unit/job relation 3 Normalized Manhattan distance, already-on-target flag, and whether this candidate is the unit's current commitment.
x(state, job, unit) = [global43 | job26 | relation3]

Continuous values are scaled—money, counts, time, price ratios, and Manhattan distance—so the network does not receive wildly different numeric magnitudes.

Shared work

Global features are calculated once per turn. Static job features are calculated once per candidate. Only the three relation features change from one unit to another.

Compact replay

Rollouts store globals and job statics once per time step, plus small target and unit position arrays. Unit/job distance features are reconstructed when sampling, avoiding a large duplicated candidate matrix for every unit transition.

The Q-network

The model is a multilayer perceptron. It has no recurrence, convolution, attention, or separate output head per action. A batch dimension simply lets it score many candidates in parallel.

Greedy play

Submission-time epsilon is zero. The agent takes the allowed candidate with the highest Q-value. Equal values break toward the lowest candidate index, making inference deterministic for a fixed observation.

Exploration

During collection, epsilon-greedy selection sometimes chooses a uniformly random allowed candidate. Epsilon decays by the number of observed unit transitions, not by episode or wall-clock time.

Training uses the PyTorch mirror in training/network.py. Deployment transposes and exports its linear weights into weights.npz, which policy.py evaluates with NumPy. Tests pin both forward passes to the same result.

Reward shaping

Money alone is sparse and initially punishes useful investments. Buying a seed lowers cash immediately, while its harvest may arrive many turns later. The recorder therefore adds a potential term based on cash and the current market value of crops in the shed, carried by units, and already available as plant yield.

rt = Δmoneyt/1000 + γΦ(st+1) − Φ(st)
rterminal += +1 for a win, −1 for a loss

Φ is also divided by 1000. Potential-based shaping gives earlier learning signals while preserving the underlying policy objective when applied consistently.

Double DQN target

Replay accumulates up to n_step rewards. The online network chooses the next candidate, while the target network supplies its value. This separates selection from evaluation and reduces ordinary DQN's maximization bias.

Rt(n) = Σk=0..n−1 γkrt+k
a* = argmaxa Qonline(st+n, a)
y = Rt(n) + γnQtarget(st+n, a*)

At a terminal transition, the bootstrap term is zero.

Optimizer

Adam lr 1e-4

The online network is optimized against the target using smooth L1 (Huber) loss.

Stability

grad clip 10 target sync 2000

Gradient norms are clipped, and the target network periodically copies online weights.

Default horizon

γ 0.997 n-step 3

A high discount factor reflects the long delay between farm work and realized sales.

Rollouts and replay memory

Each episode is stored as a struct of NumPy arrays by training/collect.py. Variable candidate and unit counts are padded only within an episode, with boolean masks identifying real rows. Batches are serialized as compressed .npz without pickle.

Stored each step

  • 43 global features
  • Static features and targets for candidate jobs
  • Unit positions and existence mask
  • Chosen and committed job indices
  • Money, potential, rewards, and truncation count

Rebuilt when sampled

  • Unit-to-target Manhattan distance
  • Already-at-target indicator
  • Committed-candidate indicator
  • Full 72-feature candidate rows
  • Padded next-state candidate batch

training/replay.py samples an episode, time, and active unit. Its buffer combines recent FIFO episodes with a fixed-size reservoir sample of older evictions. The recent segment follows the current policy; the reservoir keeps older state distributions visible and reduces catastrophic forgetting.

Configuration note: the standalone trainer defaults to an 800-episode buffer with 35% reserved for historical sampling, an epsilon floor of 0.15, 16 episodes per round, and 400 gradient steps. Persistent league training reads its values from agent.toml, so verify that manifest before a long run.

The model and the market controller

Field choices and market choices happen in parallel, but only field choices are learned. market.py deterministically builds up to ten orders per turn.

Sell

Crops are sold according to the configured immediate, price-threshold, or shed-pressure policy.

Hire

Hands are hired early in the day up to the configured limit while preserving a cash reserve.

Buy seeds

Crop scores combine profitability, current price, town demand, opponent supply, and season feasibility.

This separation means the Q-network learns from states partly produced by a fixed economic policy. Changing market rules changes the data distribution even when the neural network and feature layout stay unchanged.

From training to submission

  1. Train the PyTorch online network Rollouts, replay, optimization, and target-network updates run under the training package.
  2. Evaluate greedily in the arena Checkpoints play seat-swapped seeds. Paired score margin—not training return or raw money— decides whether a candidate is worth promoting.
  3. Export the inference weights Linear matrices and biases are converted to NumPy orientation and stored in weights.npz. The standalone trainer only overwrites live weights with --ship.
  4. Load once at agent import main.py loads the compressed weights into the NumPy network. Kaggle calls the module-level agent(obs, configuration) function.
  5. Build the minimal archive The exporter copies the inference allowlist and adds a root-level Kaggle shim. PyTorch, replay data, trainers, and experiment infrastructure are excluded. 
# Standalone training; --ship promotes the measured best into weights.npz
python -m agents.dqn_job_scorer.training.train --rounds 200 --jobs 8 --ship

# Build submission folder and dqn_job_scorer_submission.tgz
python agents/dqn_job_scorer/export_submission.py
Submission runtime: standard library plus NumPy. The PyTorch network exists only for training. The deployed model performs two small hidden-layer matrix multiplications for each candidate set, well inside the action timeout.
